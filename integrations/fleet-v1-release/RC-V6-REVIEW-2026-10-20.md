### 1.1 Static safety review

- **#347:** `private_path_guard.py` compares every spelling that can name the
  same file: drive, UNC, `\\?\` long-path, `\\.\` device, POSIX, lexical
  normalization and `realpath` for symlink aliases. A device namespace that is
  not a plain drive is treated as **ambiguous and refused**, not as safe. The
  strict CRLF/SHA pin remains in the harness; pure CRLF is accepted only as a
  transcription, while mixed endings, BOMs and changed fields still fail. The
  guard refuses reads of an owner-private legacy root and does not fall back to
  one.
- **#349:** the grant suite defines `WINDOWS_PRODUCER_BOUNDARY` and applies
  `@pytest.mark.skipif` **before** importing `workengine` or `fcntl`; the 13
  POSIX-only cases are skipped with `PRODUCER_BOUNDARY_POSIX_ONLY`, never run
  against a fake Windows producer. The 19-case manifest from #342 remains. A
  skip is not a pass. Windows-specific case rules apply only to Windows forms;
  POSIX case rules remain for POSIX paths. **QA snapshot AC still rates #349
  PARTIAL**: 8.3 short names (`C:\PROGRA~1\...` vs `C:\Program Files\...`)
  and unresolved drive-relative `C:..\private\evil` are reported safe, not
  ambiguous. These P2 residuals are not closed by this RC and are listed in §10.
- **#345:** `daemon_socket_path` still honours `XDG_RUNTIME_DIR` and otherwise
  uses `os.getuid()` exactly as before on Linux. Only when neither exists does
  it raise `PlatformUnsupported`, which `status` maps to `NOT_RUNNING` /
  `UNSUPPORTED_PLATFORM` / exit 2. It does **not** enable the Windows Python
  daemon, invent a uid or fallback socket, or change the Linux status/socket
  path. JSON remains ASCII-safe; the UTF-8 stdout choice is per process.
