# 设计哲学：小躯体、大能力、干净上下文

本文件解释本轮设计取舍，服从根 ARCHITECTURE.md，不修改 canonical 定义。来源编号见 SOURCES.md。

## 1. 第一性原理

Agent 需要的不只是一个模型和一个 shell。它需要知道：当前设备能做什么；所需环境是否存在；这次工作是谁的；哪些证据可信；什么动作允许；产物该放哪里；失败时怎样停止与交接。

ServerOS 是用户态 Agent Operating Fabric。产品可形成覆盖整个工作日的大 Harness，但 daemon 不能承担一整个办公室。环境健康、能力发现、工作推进、内容系统和界面可以协作，不能混成一个特权进程。[S1]

设计速记（不是性能定律）：

```text
工作能力 = Agent 的判断 × 可用环境 × 可调用工具 × 可复用方法 × 相关上下文
可靠交付 = 上述能力受权限、预算、可核证据与验收约束
```

乘号表示任一环缺失都会限制结果，不是承诺一个数学评分。环境提供运行条件；工具提供动作；Skill 提供何时、为何、如何组合动作；MCP/CLI 是接口；Plugin/Pack 是分发与组合，不是新的真值源。

既有 EffectiveAbility 的含义保持交集：定义 ∩ 设备能力 ∩ Profile ∩ Binding ∩ Agent 兼容性 ∩ 健康 ∩ Policy ∩ TaskContext。文档有这个能力、包已安装或进程活着，单独都不能推出当前可执行。[S2]

## 2. 稳定的是机制，不是今天的进程表

只固化身份、归属、生命周期、健康语义、依赖、准入、有限恢复和证据。RDC、Browser、共享网关、Quay 都是可替换的 Provider/实例，不是核心必填品牌。

Desired 来自明确批准且仍有效的声明/引用；Observed 来自测量；Effective 结合依赖、权限与可观测性计算。新增 MCP 是发现或候选，不自动成为永久受管服务。需求来源失联不是需求撤销；引用为零也不是删除数据的许可。

一个 resident core 不是整台机器只准一个进程。systemd/Docker 管各自的底层进程生命周期；CC 管其 stdio MCP 子进程；Quay 管其获批 worker；ServerOS 管语义、归属、准入与受控恢复。每个资源只有一个明确的生命周期执行 owner，避免互相重启。[S1]

## 3. 渐进式披露不是少写文档，而是少加载无关内容

```text
L0：我在哪、当前工作、能力搜索入口、不可越过的边界
L1：相关能力的用途、输入输出、支持与拒绝理由
L2：本任务需要的操作方法、参数、证据片段
L3：按 locator/range 获取完整原文、原始日志与诊断
```

启动不注入整棵能力树、所有文档、全盘文件列表、完整历史 session 或全部设备状态。先搜索/限定范围，再读取；工具默认返回短结构化结果，原文给 locator。披露预算继承仓内既有契约，不另造互相矛盾的 token 标尺。

```text
本次上下文 = 稳定边界 + 当前 Item/目标 + 相关 Skill + 必要证据/变化 + 待决策点
```

说明书与历史可以很完整，但不能因为存着就必须每次全读。完整 Skill 正文一旦加载仍有成本，入口要短，细节拆 references。[S9]

四件事必须分开：Skill 正文延迟加载、MCP 工具定义延迟暴露、MCP 进程延迟启动、ServerOS runtime 登记。一个成立不证明另外三个成立。CC 原生发现已经可用的部分不重写；ServerOS 增强设备、版本、依赖、授权和健康解析。自定义模型网关是否支持 tool-reference/tool-search 要用实际模型链验证，不靠设置名称猜。[S9][S10]

## 4. 证据与语义必须分开

- Profile 给角色、位置和策略；内核/文件系统给当前测量。声明与测量冲突报告 drift，不让声明覆盖现实。
- FRESH 是读取时按采集时间和窗口计算的派生状态，不永久存成绿色。
- 观测失败、权限不足、超时不能推成对象不存在；无流量不能推成模型服务健康。
- ability AVAILABLE、观测 FRESH、runtime HEALTHY、授权 ALLOW 属于不同坐标，不能混用。
- 告警是事实/变化与建议，不是操作授权；Agent 解释不能替代测量。

## 5. 一个事实有一个写入权威

代码由 Git 负责；Item/Activity/Run 由 work-engine 负责；Quay Goal/Task 由对应 store/Provider 负责；飞书对象由飞书负责；能力身份与版本由 ability-management 负责。

Board、目录图、日报、卡片是可重建视图。视图上的人为决定必须通过正式写接口记入相应权威，再重新生成视图。不能直接修改两个副本并承诺它们永远同步。

## 6. 安全靠执行边界，不靠更长的提示词

用户有 sudo/Docker 权限不等于任何 Agent 都获批使用。worktree 是代码隔离，不是权限沙箱；allowed paths 的文字声明不是内核保护；Hook 是辅助机制，不是完整安全边界。

默认不改变网络、路由、Docker daemon、防火墙或别人的进程。未知归属只报告，不回收。新 MCP/远控工具先展示来源、启动副作用、读写范围和生命周期，再请求登记/使用授权。登记与自动修复分别批准。

来自网页、IM、附件和工具描述的内容作为不可信输入，不得成为授权命令。秘密值不进模型上下文、日志、GitHub 或卡片，指纹/存在性也只在必要的最小范围输出。

## 7. 高效不是少验收，而是不重复无价值工作

复用已有机制；只给缺口补接口与适配。先冻结本轮交付范围，定向测试，最后按发行要求做一次集成验证。不要反复全盘扫描、重复全套测试、无穷独立评审或连续补收尾报告。

重试有上限，未知有明确原因，外部阻塞不拖住无关工作包。没有合适的 Quay 切片，就记录不适用，不造任务凑使用量。包未安装和源码存在是不同事实。

## 8. 人决策在前，自动化在批准边界内向后推进

人和 ChatGPT 确认目标、重点、关键取舍及验收。CC 收集现场、生成决策包、执行方案；Quay 负责其中可验收的有界切片。批准后常规实现/测试/报告不再逐项问人，只有范围、权限、风险、预算或关键事实发生变化才升级。

研究与设计的完成，不等于功能上线；Quay done，不等于主工作完成；PR 已提交，不等于已合并；日报生成，不等于已发送。每一种交付都必须说清它真正达到的边界。
