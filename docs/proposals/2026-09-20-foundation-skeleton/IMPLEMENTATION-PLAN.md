# 单轮实施计划与固定验收

目标：搭出可使用和可逐份审阅的骨架，然后停止本轮。不是实现所有未来能力，也不是再交付一轮纯研究。开发允许直接推进；共享线上变更仍需单独准入。

## 0. 开始前的一次短对账

读取根架构、各仓库管理入口和本目录；核实当前 repo revision、自己/他人工作树、已存在的 resource Slice、模型/工具接口和目标目录角色。只检查相关路径，不重新做全盘迁移或网络诊断。

创建一个本轮正式协调 Item，复用 work-engine 分配与合法生命周期；一个 Item 可有多个 repo context/Activity/Run。每个 repo 独立 clean worktree，明确写 owner，禁止抢占同一文件。若 ID 分配器真实冲突，不编号、不建第二数据库；先保全已做代码/具名候选并继续不依赖 Item 写入的安全工作，最终如实报告生命周期缺口。

外部模型请求继承已批准费用预算。不要无限派研究 Agent；并行只按互不重叠文件分工，最后串行整合。

## 1. 工作包 A：能力家族与分发

在 ability-management 按其唯一管理协议完成：

- 现有能力→目标家族映射，复用稳定身份和现有 taxonomy/pack 机制；不机械移动平铺目录。
- 每个簇有真实输入输出、拒绝条件、依赖、权限和可验收产物；细节按需引用。
- 新增或合入一个 cc-quay-delegation 主 Skill，及必要的卡片/工作台适配增量；不为每个步骤建一个微型 Skill。
- reusable payload 变更经 sync/指纹/Revision 更新，原历史保留；实际通过验证的兼容与安装才登记，不宣称所有设备已可用。
- ServerOS composition 从明确 ability commit 构建，整个包不能把 catalogue 全塞启动上下文。

交付：生成的 Ability 地图、人类入口、机器可读能力对照；source/pack/pin/build 关系可复核。

## 2. 工作包 B：环境底座接口

复用/合入已在推进的 Resource Observation & Self-Health；本轮不另做平行采集器。实现或适配统一 snapshot、按读取时间计算 freshness、profile/live join、quota 双值、shm、文件系统与 role 分离、用户/共享服务隔离展示。

提供注册候选的最小闭环：显式模拟/受控的新 runtime → 候选 → 用户范围选择 → 合法注册计划/登记 → 重新解析。测试默认只观察、UNKNOWN 不自动管理、会话结束不无限重启、来源失联不撤回期望。auto-recovery 线上开关保持既有值。

若该代码归其他活跃会话，锁定它的接口并用记录的现有 snapshot 构建消费者；可以完成消费者骨架，但不能声称缺失的新观测已上线。最终给一个集成点，而不是持续等待后又重写一份。

## 3. 工作包 C：三板块状态、告警与恢复

按 OBSERVABILITY-CARDS.md 实现确定性模型、subject 人话解析、共享 renderer、实际 Feishu card JSON 及预览。能力层拥有通用代码，ops 只配节点/对象/目标。

必须产出正常、部分未知/过期、单异常、观测失败、混合与仅恢复六类样例；不改变线上告警账本、游标和 timer。修正误导信息，不用换颜色掩盖事实不足。严禁把合成故障写到生产 registry。

交付手机窄屏/桌面可视预览。能在当前已授权渲染工具看见就验证布局；不能回读飞书客户端则明确尚未完成该层验证，不阻碍离线代码与产物交付。

## 4. 工作包 D：信息到交付工作链

最小可运行链复用 work-engine 与既有能力：

授权输入快照 → 结构化认识 → 候选/跨项目看板 → 选中 → 单项 brief → design/plan → 实施/验证记录 → 日报/反馈。

使用获准的现有脱敏输入或明确 SAMPLE fixture；不默认调用真实云 API。至少包含两个项目、今日重点、P0/P1、等待、取消/替代、PR未合并和成功完成划线案例。不能先要求每个候选有长 brief 才能入看板。

每环节给一个可运行入口或模板+真实执行协议，输入输出可校验、相邻引用可解析。不填泛泛 TODO 再宣称全部可用。未实现真实云抓取的适配器明确不支持 live，离线契约仍能运行。

关注源清单、飞书知识库/云盘/我的文档库三空间地图、磁盘三级地图均有样例与覆盖/未知分母；不新搬数据、不擅自整理云对象。目录按 role 解析，map 生成遵循现有权威。

## 5. 工作包 E：CC → Quay 一轮

按 QUAY-DELEGATION.md 读取真实安装 surface，产生父工作→PHASE/AC/Task 对应关系并回读；在独占范围驱动一次与本轮有关的有限验证，收集真实结果并生成 Quay 日报段。

不用笼统“任务创建成功”验收。记录执行 count、判据语义、输入 SHA、真实 diff 和 artifact；没有支持/授权就拒绝，完成其余骨架并把 Quay live 状态单列。不要给旧 LiteLLM 全量 init/loop，也不改 Quay 自身仓库。

## 6. 工作包 F：发布与预览首页

一个入口供用户检查：

```text
START-HERE
  环境/能力地图
  状态、告警、恢复预览
  磁盘与三种飞书空间覆盖页
  关注源与认识变化
  跨项目看板
  单项 brief/design/plan
  Quay Goal/Task 对应、执行结果
  日报与 ChatGPT Decision Packet
  已实现 / 样例 / live未验证 / 待部署清单
```

复用 records 的获准发布面，不把 live DB、原始秘密或未批准公司内容上传。源码提交到对应 repo 分支，产物摘要和代码/能力/fixture revision 固定在一个 release manifest；跨 repo 不是原子事务，要验证所有 pin 可达、不能半发布就改 active pointer。

## 7. 固定测试，不无限加门禁

至少覆盖：

1. 单核心边界、无业务云 SDK 进入 daemon、无硬编码设备清单。
2. 薄 bootstrap 可发现相关能力，长引用不默认进上下文；缺 provider 不假绿。
3. 候选登记的未授权/去重/不同生命周期/来源失联反例。
4. 观测失败不判对象消失；freshness 会随时间过期；profile/live 冲突；quota/shm/同挂载多 role。
5. 状态卡准确三块；告警人话；未知不绿；无流量不绿；未曾通知不造恢复。
6. 看板先于单项 brief；取消不当成功；PR未合并独立；来源重复不重复建需求。
7. Quay Goal/AC 与 Task 不混用，非法/不支持入口拒绝、零执行不通过、实际 Task done 不关闭父 Item。
8. GitHub 发布白名单与跨文件版本一致；不序列化 secret。
9. 干净外部目录安装产物并走实际入口，不能只在源码目录通过。

先定向测试；如既有发行契约要求全套，最后只做一轮必要的集成全套。失败定位后定向复跑。基线失败不能泛化成“都无关”，也不能在另一树 stash/reset 验证。无需付费 completion、生产压测或主动破坏服务造故障。

## 8. 线上切换与权限

本轮无需为了“骨架完成”重启所有服务。安全范围包括：自己 clean worktree 中开发、受限测试、隔离安装、生成预览、白名单 commit/push。

需要另行集中批准：serverosd promote/restart、修改 active registry、覆盖现用 CC 插件/Hook、切换生产卡片 timer、真实发卡、启用每日定时任务、云端创建/移动/编辑、隧道/网络/监听/防火墙/共享 Docker 配置、秘密变更。批准清单写目标、影响、前后检查与回退，不逐文件打断。

获批后只执行名单中动作；否则交付 staged artifact 和精确部署说明。不得把 CODE-PASS 冒充 LIVE-PASS，也不因待批准而丢掉整轮成果。

## 9. 完成与停止

最后按维度报告，不用一个 PASS 吞掉全部：

| 维度 | 可接受证据 |
|---|---|
| 架构/能力骨架 | 对照表、生成图、契约验证、版本/pin |
| 离线工作链 | 一个完整可回放案例与反例 |
| 卡片 | JSON验证 + 同源可视预览；飞书实际回读单列 |
| Quay | 真实 Goal/Task/执行/结果，或具名 live 阻塞 |
| 分发 | 干净构建与隔离安装 smoke |
| 线上 | 未变 / 待批准 / 经批准已切换及证据 |
| GitHub | commit、分支/PR、可回读入口、release manifest |

只交文档和空目录 = 未完成骨架。fixtures通过 = 该离线路径通过，不是所有连接可用。现场已有缺口、他人 WIP、未批准网络操作不无限追加为本轮工作。完成固定范围后停止，由用户从产物开始逐个环节打磨。
