## Hardening review round 3 — independent counterexamples (2026-10-22)

The independent reviewer supplied seven synthetic tests at
`RUN-0046/.../client-independent/f0d54ae/probe_client.py`; all were RED. They
are kept byte-identical and re-run against this head. Each finding and its
resolution:

1. **New project required static per-project authorization.** The Skill's table
   said a project needed the machine's project list *and* `create_allow`. A new
   project inside the owner's configured `project_roots` has no static row to
   name. Resolution: existing-project sessions keep the static list; a new
   project is authorized by the owner-configured root.
2. **Codex inherited ambient provider credentials and lost the runner
   `TMPDIR`.** Resolution: an explicit environment removes provider credential
   variables, sets the evidence `TMPDIR`, and keeps a fresh isolated
   `CODEX_HOME`. The receipt records names seen/removed, never values, and
   `login_copied: false`.
3. **Client claims could be filled by the side probe.** Resolution: CC claims
   come only from CC's interposed wire; Codex `tool_count_actual` and
   `project_create_capability_actual` come only from the app-server. The probe
   remains `OWNED_PROBE_*`, a separate chain.
4. **`select()` + `readline()` lost a buffered reply behind a burst
   notification.** Resolution: `stdio_framing.LineFramer` reads raw bytes,
   caps line/look-ahead, and queues whole frames. Burst tests cover both
   `CodexServer.request` and `fleet_owned_probe._call`.
5. **CC `prepare` accepted an existing output and `build` removed `plugin/`
   before validation.** Resolution: `prepare` refuses a non-fresh root, and
   `build` never calls `rmtree`; the generator validates the owned entry/config
   and refuses before writing.
6. **Codex fixture copied content through a symlinked skill directory.**
   Resolution: `check_skills_source` rejects symlink ancestors and members and
   escape before any output is created; the normal shared eight still copy.
7. **A connection string could be read as a client tool list.** Resolution:
   only real frames count; no model turn means `MODEL_SKILL_BEHAVIOR` and
   `CLIENT_E2E` stay `NOT_RUN`. `CC_CLI_CONNECTED` is separate from
   `MCP_INITIALIZE_OK`/`TOOLS_LIST_OK`.

The seven cases are GREEN at the hardening head. The same source also passes
the regenerated package plan/readback/rollback/rehearsal and the real owned CC
and Codex no-model runs. No model turn was attempted in this batch; the prior
CC `BLOCKED_MODEL_AUTH` result stands and is not retired by a probe call.
