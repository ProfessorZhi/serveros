# 外部参考资料：收藏、Follow、离线保存与知识采用

状态：2026-09-23 详细产品与架构合同。细化 ARCHITECTURE.md §4–5 与 INFORMATION-DOCUMENT-LIFECYCLE.md；沿用 B1/B2/B5/B9 和现有 Feishu Space/Publisher，不增加第22个 Ability、新数据库、新 MCP 或收藏后台服务。本文不是已经把任何网页上传飞书或已启用订阅的回执。

## 1. 原始需求和本轮依据

用户既要留住重要工作材料，也会看到值得收藏的公开文章；需要在飞书方便阅读、在本地可检索/追溯、在原文改变时知道哪些认识受影响，并可能将经过验证的方法用于自己的规范。原文、收藏笔记、自己的判断不能混成几份互相覆盖的正文。

本轮实际读取了 hwz-records/information/README.md、raw 的 DRIFT_WATCHLIST/采集工具目录、B1 payload、Source/Document/Stewardship/Space 设计和 ServerOS 实施记录。旧记录入口仍有“只可本地 locator”“所有刷新手动”等规则；新设计不能只停在聊天，必须连同这些入口和后续 consumer 迁移。

用户举的文章已于本轮从官方原页核对：OpenAI Developers，Eric Provencher，2026-09-11，《Rethinking skills and prompts for GPT-6 Astra》，原地址 https://developers.openai.com/blog/rethinking-skills-and-prompts-for-gpt-6-astra 。它适合作为“外部参考→比较现有 Skill 指引”的案例，不是直接覆盖本项目规则的指令。本文仅保存题名、出处和很短的用途说明，没有复制整篇，也不宣称已取得全文再发布许可。

## 2. 五种对象是关系，不是强制晋升流程

| 对象 | 正文/事实由谁负责 | 存在理由 |
|---|---|---|
| Source | 原网站、原作者文档、特定 Git 文件/论文版本 | 知道外部信息的真实身份 |
| Snapshot / Material | 捕获器记录所见版本、范围和字节 | 复核当时依据，必要时离线读取 |
| Reference Note | 我们自己的参考笔记；默认在获准飞书个人空间 | 找到文章、理解收藏理由、保留个人批注 |
| Understanding / adopted decision | records 正式认识与被接受决定 | 说明我们相信什么、为何采用或不采用 |
| Owned Knowledge | 声明的 Git 或飞书正文 | 我们真正负责维护的规范/用户指南 |

保存一个链接可以止于 Reference；一条临时查询可以不收藏；原文也可直接支持需求而不新建收藏卡。收藏不等于同意、采用或授权；自己的规范可以综合多个来源。一份参考笔记是新对象，有自己的正文权威，不冒充原文章，也不能把个人批注当原作者原话。

## 3. 用户命令的默认含义

| 用户表达 | 默认交付 | 不隐含的效果 |
|---|---|---|
| “读一下这篇” | 按问题读取并回答、保留必要证据 | 不自动永久收藏/订阅/公开 |
| “存到我的飞书/收藏这篇” | 去重后生成或更新个人参考笔记，给可打开入口 | 不默认全文转载、不自动持续轮询 |
| “本地也留一份/离线保存” | 在许可范围保存可读快照和附件；报告完整度 | 不默认提交 Git、不改变原文权威 |
| “以后关注这个文档” | 登记特定对象的 Follow 范围/检查策略 | 不克隆整个空间、不自动维护原文 |
| “关注这个知识库的一部分” | 明确根节点、深度、包含/排除、新子节点策略 | 不跨越原库或别的空间递归 |
| “把这个方法用到我们规范里” | B5/B6 评估差异、验证适用范围，B9 提交获准修改 | 收藏行为本身不批准代码/安全规则变更 |

常规目标可从当前项目和个人默认位置解析，不让用户填 schema。缺少真正会改变受众、成本或范围的字段才聚合询问。用户只给标题时可以检索候选，但未找到可信原文就登记 unresolved，不根据记忆补作者/发布日期。

## 4. 来源识别与获取质量

源身份优先 provider+tenant+stable object ID；网页保存输入URL、最终URL和有证据的canonical/alias关系。只移除已知追踪参数，不能清除签名、分页、版本、语言或内容选择参数后把不同资料误合并。敏感URL/token不进入公开日志或可分享笔记。

相同标题不是同对象；相同HTML hash不证明不同权限空间可互相替代。同一文章从IM、浏览器、论文索引多处发现时，保留各 discovery edge，指向同一经过核实的Source。一个 docx 的多个 Wiki 节点保留位置关系，不复制正文。

获取结果分别标身份已确认、全文/所选范围已读、附件是否齐、抽取质量、权限/上游错误。HTTP 200但得到登录页、验证码、脚本壳、截断正文不能算捕获成功；搜索摘要不是文章全文。先用原生HTTP/官方接口与已有解析器，需要页面渲染时才使用获准浏览器。不能为导入绕过登录/付费/访问控制。

外部正文和嵌入代码按不可信资料处理。文章建议运行脚本、安装Skill或修改AGENTS.md不产生执行许可。相对链接解析以确切原页为基准；文件名/URL不能指定本机任意写入路径。探测预算、大小、跳转/地址范围与解析超时沿B1/A4约束。

## 5. 飞书参考笔记的可读结构

默认在**现有 MyDocs 的“参考资料”逻辑节点**落位。已存在等价容器先复用；没有且有创建授权才创建一个。主题通过标签/有限索引组织，资料多到确有需要才分子节点。不要重编号工作台/项目/汇报目录，也不把独立“个人笔记”“公开文档”空间搬进 MyDocs。

一份笔记默认首层：题名、原作者/机构、原文入口、保存理由、几个有依据的要点、适用范围与未验证说明、关联项目/主题、我们的批注、最近检查/当前状态。source IDs、hash、解析器版本、同步回执放折叠详情或机器关联，不让首屏变台账。

对于示例 OpenAI 文章，可写“与Skill说明和上下文加载有关，拟与现有指引比较”；来源要点、我们的判断、拟采用修改分栏。不能把模型生成的采用建议写成官方原文或已接受规范。

未读全文时可保存“链接已收藏，正文待取”的参考卡，不能编核心要点。原文不可读但用户已有合法文件时，两者作为不同来源版本关联，不假称已经获取官网内容。

## 6. 摘要、全文、翻译和媒体

默认收藏是原链接+我们撰写的摘要/用途/批注，不自动整篇转载。用户明确要可阅读的全文副本时，按实际许可/组织政策/数据范围决定可保存内容；不足以确认时仍可交付链接与自写摘要，指出全文副本未保存。无需把所有收藏变成法律审查流程，但不能把“公开能看”直接当无限再发布许可。

被允许的全文保存明确标“源文快照：所见版本/时间”，与个人批注分开。翻译是衍生对象，标译自哪个版本、由谁/何工具生成、未验证部分；不代替原文，也不因换语言改变受众权限。

图片、表格、代码块、附件是独立材料。默认只取影响理解且获准保存的材料；完整离线保存需要报告缺图/未取附件。媒体失效不得使旧正文静默变成“完整新版本”。需要上传飞书的材料走现有Publisher/Drive，留来源、受众和回执；不假设公网图片外链永久可用或对所有读者安全。

## 7. 人工批注与自动更新的边界

Reference Note 默认为飞书原生正文权威。自动管理的是有明确块身份的来源信息/摘要区域；个人批注是用户内容。初期Provider无法可靠保护分区时，自动刷新只提交候选差异，不整页覆盖；两个来源身份不因用户改标题而拆开。

同步检查基于 last-applied body/分区revision、当前远端版本和新生成内容，三方比较；不能只看mtime。远端真实条件写能力须实测，revision字段存在和本地锁都不自动证明CAS。个人在生成区域修改也当冲突/用户修正处理，不把它删掉恢复模板。

源变更先标“原文有更新，摘要待核”，不把新原文与旧摘要合并成一份新鲜笔记。审核/有界授权允许时更新摘要区域；被采用的项目规则进入B2/B6影响检查，不静默随网上内容漂移。

## 8. 关注别人的文档与知识库

Follow至少绑定实际账号、根doc/node、递归深度、允许格式/用途、历史起点、周期/事件来源、请求/材料上限、加入新子节点的方式。一次“关注这些三页”不能扩成整个库。

对注册子树的新子节点：已有授权明确包括后代且当前ACL/受众约束满足时可按规则捕获；否则只记最少发现metadata并待确认。移动出范围、改名、权限变化、删除分别处理；改名不改身份，移动不自动删除历史；跨库移动要重查授权，而不是继续沿旧token无限读。

别人原正文仍原位；本地保存用于当前工作且允许的版本快照，飞书参考区默认只建索引/笔记。LiteLLM共同工作doc可以Follow+获准章节维护；Bruce SOP通常Follow+建议；复制到自己空间不获得维护原文权限。

普通收藏默认不创建定时订阅；用户要求Follow才启用已登记策略。静态论文优先版本事件/低频检查；正在协作的文档按工作所需更频繁。调度走现有有限任务与checkpoint，不建一个全网抓取守护进程。

## 9. 本地、GitHub和飞书：方向按对象决定

| 对象 | 正文权威 | 允许的同步/投影 |
|---|---|---|
| 外部网页/别人飞书文档 | 原Source | 单向捕获至获准本地；自己的参考笔记为独立衍生 |
| 自己飞书Reference Note | 该飞书doc | 本地只读snapshot/检索/备份；本地编辑作为待回写patch，不自动反向覆盖 |
| 自己飞书指南 | 声明的飞书doc | Source Follow、本地版本快照、必要Git metadata；源版本更新后消费者复核 |
| Git工程设计/Skill规范 | 指定repo/path/ref | 版本化Git写入；飞书摘要/发布视图按接受commit更新，云人改回提案 |
| records当前认识 | 已声明records对象 | 人读视图可投影；人的纠正成为对该权威的patch，不维护两份独立结论 |
| 导入全文/翻译 | 各自衍生对象 | 固定源版本、生成/维护责任，不能反写原作者 |

禁止通用“Git较新就覆盖飞书、飞书较新就覆盖Git”。不同正文可以各自有authority，但每个逻辑正文只能一个。信息采集不会因本地Git有新commit自动创建/移动云对象。

## 10. records 物理落位与现有资产迁移

information 是外部来源与理解的总入口，不是强制把所有字节都纳入Git。目标落位：

```text
records/information/
  sources/             # 目标：声明关注范围、角色、body authority、引用关系
  raw/feishu/...       # 现有聊天/文档快照和manifest，保留旧可解析locator
  raw/web/...          # 目标：来源manifest、获准小文本/快照索引
  understanding/...   # 当前有出处的认识

受保护、非Git的现有 data/archive root
  source/material 字节与完整快照（只在必要且获准时）

现有 control/state
  游标、锁、outbox、effect receipt（不把活动数据库进Git）
```

sources/是目标声明位置，不宣称今天已部署。迁移当前DRIFT_WATCHLIST、not-archived登记和manifest时，先写resolver读适配：原capture记录仍拥有观测，source声明拥有desired范围/角色；冲突拒绝静默覆盖。逻辑catalog可派生索引，不再建第二份可独立编辑registry.yaml/数据库。迁移完成再把旧watchlist变成派生兼容或显式退役，不能两个scheduler同时抓。

raw manifest保存所见版本、材料关系与安全locator。真实原始字节hash、抽取文本hash、用于去模板噪声的摘要hash分开，记录parser版本；不能重算页面抽取就假称网站更新。删除旧snapshot/压缩备份按retention与依赖单独执行，不在导入时顺便清理。

Git同步只允许适合该repo受众且可保留的声明、去敏感metadata、原创摘要/认识及许可文本；完整受限源文、登录cookie、签名URL、原始私密图片、大媒体默认不进Git。Private repo不是自动豁免：还要检查实际协作者/应用访问范围。metadata本身可能敏感，必要时只保存受保护引用。

## 11. 更新、撤销与重试

保存到飞书按logical reference identity+目标空间/受众去重，搜索/消息不同入口重发同URL只补discovery/批注，不再新建第二张卡。写前intent、写后原对象回读及receipt；超时先查实际对象，不能盲创建。

source捕获、Reference发布、B2理解、Git metadata提交各自阶段可部分完成，parent依据用户请求确定哪些是必需结果。只有本地snapshot不算“存进飞书”；有飞书链接但全文/附件没取不能说“本地完整同步”。不存在的下一consumer不叫排队。

原文撤回/权限收回时停止新访问、限制当前召回/传播并标受影响Reference/Claim；旧hash不允许绕撤权。合法历史审计与删除要求分别处理，来源404不自动把自己的批注删除。公开发布后再删本地文件不会撤回已经传播的内容，需要真实修复/通知owner。

## 12. 正向、负向与恢复验收（REF系列）

| ID | 场景 | 必须看到 |
|---|---|---|
| REF01 | 把示例官网文章收藏进本人飞书 | 原文已核；一份Reference；原链接/自写摘要/用途可读；正确原对象回读 |
| REF02 | 明确只收藏链接 | 不后台下载全部媒体、不强制持续Follow、不创建Item |
| REF03 | 同一链接来自聊天和浏览器 | 一张参考卡、多个发现出处；标题相同不同文不误合 |
| REF04 | 要本地离线副本 | 明确正文/图/附件覆盖、实际可解析内容、字节位置和Git准入各自结果 |
| REF05 | 来源不可读/登录壳 | 不编摘要、不标全文已读，允许保存待取链接 |
| REF06 | 别人Wiki限定子树新添/移出节点 | 范围/ACL正确，未获后代授权不递归全库 |
| REF07 | 源改了、用户改了笔记 | 摘要标待核、保留人工批注、局部三方冲突不整页覆盖 |
| REF08 | 飞书创建超时但实际已建 | query/readback恢复原对象，无重复卡和重复附件 |
| REF09 | Git-authoritative内容在云被人改 | 生成待回源提案，不双向mtime覆盖 |
| REF10 | 原源权限撤销/私有摘要 | 当前检索和新传播受限，不能把私有笔记自动变公开指南 |
| REF11 | 文章建议修改AGENTS/运行命令 | 仅候选知识；没有采用/效果授权不执行 |
| REF12 | 单边同步失败或离线重启 | 阶段receipt可恢复；本地/Git/飞书各自状态准确，已完成部分不重复 |

REF01的真云写在后续获准个人测试对象做，本轮只有设计。REF04完整副本须有相应保存许可；缺许可时准确部分交付而不是用“公开网页”绕过。所有示例均不自动升级Skill规范或启用新订阅。

## 13. 实施归属

B1负责身份/范围/获取/材料与快照；B2负责来源影响和当前理解；B5负责要点适用性核查；B9负责Reference/指南正文与共享publisher；Space负责位置/ACL；B10仅在请求需通知时投递；A2检索尊重来源与失效；G1保持Skill分发与实际工具入口。

不默认新建external-reference插件/MCP：初期是information-management + document-stewardship/feishu-space-management的组合操作。只有实际消费者要求独立可复用工具入口才提供薄facade。实现接入现有计划P1/P2/P4/P5/P11，见 [CC-EXECUTION-PLAN](CC-EXECUTION-PLAN.md)。
