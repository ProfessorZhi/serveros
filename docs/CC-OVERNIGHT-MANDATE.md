## 执行授权与边界

延续本会话已有的源码/配置修复、必要测试、提交、推送、PR 集成，以及本人受管开发环境的安装更新授权。方法由 Native Agent 选择，原生工具直接路径保持可用。默认先做 W1 的 evidence 无效 Run 拒绝，再按依赖推进 W2–W7；已交付部分不重做。

不扩大生产写、ACL/受众、付费业务请求或外联授权；不生成虚假人类批准；不接管别人的会话，不覆盖 WIP，不删除未知或受保护历史材料。有效范围内的非破坏性目录修正、producer 修复和可回退物化按计划实施；清理保持具体审批边界。

## 夜间推进方式

1. 用一个短 checkpoint 记当前包、实际版本、已发生效果、必要证据、下一动作和局部阻塞。普通读写不各开 Run。
2. 选择下一项能直接改善真实链路的工程，实施、定向验证、集成、安装/读回；包完成后继续。
3. 遇到需要用户的重要决定或无法替代的外部操作，先备好对象、scope、版本、步骤、预算与回退，写入待决定清单；仅暂停该分支，转做其他包。
4. 已授权范围内的普通实现取舍，采用合理、兼容、可回退方案并记录，不因用户睡觉而停工，也不把沉默当新增授权。
5. 发现失败先定位并修复本范围问题。不要用“量得更准确”“又写了一篇报告”代替关闭实际断点。
6. 达到上下文压缩时保留稳定入口继续；客户端真到预算、会话或工具硬限制时使用其实际支持的恢复机制。不要编造后台会继续、不要无限新开会话规避预算。
7. 未解决的问题只有在阻碍当前验收或形成明确错误时进入本轮范围，不无边界扩题。没有变化不重跑全套测试。

## 不得作为停止理由的情况

- 完成了本轮几个 PR/Run、表中 21 行已填、代码在盘上、服务 active。
- 所需功能由 Native Agent 实现而没有单独 Skill、timer 或 MCP。
- 未引入 priority、feedback 表为空、没有真实事故或生产变更。
- 脏 records 不能整体快进、旧目录不能清理；这些不阻止精确读面/producer 等独立修复。
- 一份长期 grant 或外部生产通道缺失；这不阻止已授权的普通开发和其它工作包。
