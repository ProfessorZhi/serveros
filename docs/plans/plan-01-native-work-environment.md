## 3. 工作包与完成条件

顺序按实际依赖选择；一个包遇到外部阻塞，转做其它已授权包。一个 PR 或 Run 完成后立即继续，不把包结束当整个任务结束。

### W0：建立准确的小范围起点

核对 Item/Focus、当前源码与安装、活跃工作和本包授权。复用现有运行记录，仅对独立执行开 Run。维护一份短 checkpoint，指向对应需求、实际改动、测试/效果、待接收子任务与下一动作。

**完成**：知道当前可推进的具体目标和写域，不重开全机盘点。证据、日志与临时文件使用明确的数据盘路径。

### W1：工作与证据完整性、正式文档实际消费

**owner/落点**：work-engine 的 store/CLI，ServerOS workchain/reader，records 对象 owner。

- 优先修复 `run evidence` 接受不存在 Run 的缺陷；验证 Item/Run 存在及归属、locator 合法、重放与冲突。
- 复用 PR #92 的固定版本 reader，不重新实现同一功能。确认正式入口实际消费正确卡片/brief，不只改善 MISSING 文案。
- MKT 五卡与 LIT-0220 卡已有合并记录，先核版本，不重复创建。补卡不自动选择 Focus。
- 按 AC/Completion Boundary 处理必要文档与 deliverable 类型；不强制所有 ACTIVE Item 都齐备全部文档，也不以 feedback=0 阻止 Outcome。

**完成**：错误 Run 明确拒绝且不落记录；合法重复幂等，内容冲突具名；实际工作 reader 读到应读版本；独立问题修复后集成到真正消费者。不能覆盖 dirty records 来达标。

### W2：决定到认识、需求与 Focus

**owner/落点**：semantic writer、candidate API、Work owner、现有 C1/C2 人类入口。

- 来源/认识/需求版本绑定，处理接受、修改、合并、拒绝，正式目标唯一对应 Item。
- LiteLLM 工作文档与聊天优先对账；已解决问题不复活，开放问题不误关。
- 普通事实消费有效 standing policy；业务决定须真实来源。prepared/capture/accepted 分开。
- 已选工作继续，Focus 完成后归零。P 级没有值不构成已选任务的阻塞。

**完成**：实际决定只作用于被选范围、重放不重复建对象、冲突不覆盖；必要人类输入缺失时准备具体问题包，其余工程继续。

### W3：本机 Parent、Session 接任与有用委派

**owner/落点**：Agent Control、native Session Provider、continuation adapter、bounded executor。

- 先验证当前 launcher/adapter；不拿 10 月 5 日的失败断言最新版本仍坏。
- 本机新 Session 在正确 epoch/范围接任；不接管他人 Session，不改旧不可变绑定。
- 实际委派一项对本轮有用的实现/调查/验证，Parent 接收并采用结果。
- 控制能力限定自身 Item/epoch/grant，工程执行边界可核，未知 effect 不盲重试。
- 分开处理交互会话已有开发授权与无人续跑的机械 grant；缺后者不封死正常开发。

**完成**：真实受限 Parent 能使用所需控制面，换 Session 后继续，重复/过期结果被正确处理。可用性不得靠放开万能 Bash 或扩大文件/凭据范围换取。

### W4：长期签发、环境及需要的外部能力

**owner/落点**：B10 trust/issuer、A4/A5 Binding、A9 Provider、G1、research-exchange。

- 完成受限执行域读不到私钥、不能改信任根的真实方案、安装与校验准备。签发新鲜度与委托生命周期分开。
- 需要独立主体/特权操作/实际批准时给精确对象、步骤、效果、预算和回退，仅暂停该范围。
- 在实际任务需要时接上生产只读或研究 Provider；本地监控不是 A9 证据，fixture 不是真实研究。
- 不能用同 UID 自签、fixture 或自填 VERIFIED 创建权限，也不要求付费模型探测才能验证普通工程。

**完成**：可独立完成的代码/配置/安装器均完成；所需实际通路取得正向结果或准确外部缺口。支持/就绪/授权/执行模式分别报告，不能把其它包也标成等待。

### W5：AC 到 PR、报告、文档与 Outcome

**owner/落点**：TestRun、Work Engine、report、document owner。

- 复用证据生成实际交付报告，链接同一 Item 的验收；对齐待决消息不充当交付报告。
- 修 B9 profile 的实际契约/派生状态错误，按既有文档关系和权限做局部更新或内容完整的 patch proposal。
- 实现、验证、调研、报告任务均能结束，不强制代码或 PR。
- 根据实际完成边界记录 Outcome；Parent 接收子任务、测试通过和人类业务验收不是同一个动作。

**完成**：一项真实目标形成可消费交付，报告可追溯，投递/更新有 readback；没有为了验收制造空文档或无意义写入。

### W6：目录、深度与人读呈现

**owner/落点**：workspace-management、ops、B1/B9、各 producer。

落实目录合同 D01–D07：先改默认 producer，再做明确版本读面与 consumer 切换，最后处理已授权历史批次。遵守相对语义根的深度目标，保留有意义身份层级；native/vendor/release 子树不机械扁平化。

本包必须产出实际变更与 reader 使用结果，不只输出 findings。自有非破坏性新物化、已核实声明和允许范围内消费者切换直接推进。清理/移动/退役前用新鲜活动快照；未知、WIP、有效 lease、LIT-0103/0104、唯一证据不碰，未获具体批准的删除留 proposal。

**完成**：新输出不再写已确认错误位置，导航和默认入口清楚，深度超额有具名理由，旧消费者可恢复，活动开发未中断；飞书/报告涉及可见改动时检查手机可读性与人工区保留。

### W7：端到端与少量效率对照

用一条实际已接受目标贯穿 W1–W6 的适用部分，覆盖本机接任和有用子任务；不重做已完成业务目标。若选择 ServerOS 目标就按 ServerOS 报告，不借它宣称 LiteLLM 全部验收。

用 1–2 组有代表性的可比任务开始效率核对，保留相同目标、基础边界、模型和工具条件，在独立会话配置下对照。读实际 usage/缓存、首个有效动作、耗时、人工介入和返工；不改全局插件开关，不建立 benchmark 平台。修无收益的额外上下文与流程，没有数据的部分保留未验证。

**完成**：核心日常链真实可用；21 项需求各有实现方式与证据边界；无法发生的稀有事件具名，不以此重做全树。输入/版本/风险未变不再扩大测试。

## 5. 验证、集成与退出

每个包只留必要的代码/配置差异、相应验证与实际消费者读回。相关验证通过后立即提交/集成/安装或准备安全切换；不是再次全面盘点的入口。发布构建使用明确 revision，保留 previous，保护活跃客户端缓存与其他服务。

维护一个短 checkpoint 和既有 ledger 的相关行。不要不断给万行历史台账追加长叙事来充当进度；历史留原处，当前入口只指本轮事实与下一步。

**整个任务的停止条件**：

- 完成：本次接受范围的实现、必要安装与核心真实旅程完成，目录范围达标，限制准确；
- 部分完成：所有独立可执行工程已按逐项证据完成，只剩明确外部条件，具体操作包与恢复入口齐备；
- 时间/预算/客户端限制：如实保存 checkpoint，列出已实现和未实现，不能称全部工程完成。

普通 PR/Run 结束、看板为零、缺 P 级、无 feedback、一个待审批提案、未知历史目录，都不是整体停止条件。做完一包就继续下一包；不得反复索要已授予的普通工程权限。
